# LinguaSeeker 工作流说明

## 项目概述

LinguaSeeker 是一个面向医学遗传学文献的自动化证据提取平台。系统将多语言医学文献作为输入，通过五个阶段的流水线处理，输出符合 ACMG 标准的结构化变异致病性证据，供临床专家审查使用。

---

## 五阶段工作流

### Phase 1：文献获取

**目标**：从多种来源获取医学文献 PDF 全文。

- **输入**：用户提供的关键词、DOI、PMID，或直接上传的 PDF 文件
- **处理过程**：
  1. 多源文献检索（Crossref、PubMed、OpenAlex 等 15+ 数据源）
  2. PDF 全文下载（含多级回退策略）
- **输出**：文献 PDF 文件（及获取元数据）

### Phase 2：文档解析与数字化

**目标**：将获取的 PDF 转换为结构化的可处理文本。

- **输入**：Phase 1 输出的 PDF 文件
- **处理过程**：
  1. 文档解析（本地 + 远程解析后端，提取文本、表格、图片、公式）
- **输出**：按页组织的 Markdown 文本、文档元数据、提取的图片

### Phase 3：跨语言处理与证据提取

**目标**：消除语言障碍，从文献中精准提取与变异致病性相关的证据。

- **输入**：Phase 2 输出的结构化文档
- **处理过程**：
  1. 文本格式化与语言检测
  2. 非英文文献自动翻译为英文（保持医学术语一致性）
  3. 原文与译文双轨并行提取证据（基于 ACMG 证据字段目录）
  4. 证据源定位（将每条证据精确回溯到文档中的原始位置）
  5. 证据分组（按基因-变异对聚合）与证据链构建
  6. 质量审查（源有效性、缺失项、矛盾检测）
- **输出**：双轨证据数据（原文 + 译文）、证据链、质量报告

> **当前实现状态**：双轨交叉验证是设计目标。当前实现已包含自动翻译 + 多阶段证据提取流程。

### Phase 4：实体标准化与知识对齐

**目标**：将提取的实体名称统一到国际标准命名，并与权威数据库交叉比对。

- **输入**：Phase 3 输出的双语证据数据
- **处理过程**：
  1. 从双轨证据中提取候选实体（基因、疾病、表型、变异）
  2. 确定性精确匹配：基因→HGNC、疾病→OMIM、表型→HPO、变异→ClinVar
  3. 匹配结果分类：唯一匹配（标准化）/ 多候选（待消歧）/ 无匹配（未映射）
  4. 持久化：标准化实体、证据-实体绑定、规范证据记录
- **输出**：标准化实体绑定、规范证据记录、匹配状态报告

> **当前实现状态**：实际实现采用 `precise_match`（精确匹配）和 `similarity_match`（相似度匹配）两阶段策略。

### Phase 5：双语可视化与专家审查

**目标**：为临床专家提供直观的审查界面，并将审查反馈用于系统持续优化。

- **输入**：Phase 4 输出的标准化证据
- **处理过程**：
  1. AI 助手：对话驱动的文献处理入口，拖拽 PDF 或输入 PMID 即可触发全流程，SSE 实时反馈进度，内联证据卡片支持逐条编辑
  2. 任务看板：全生命周期任务监控，支持批量重试/删除/导出，Delta 审计日志记录所有修改
  3. 证据工作台：左侧原文 Markdown + 右侧证据卡片对照视图，点击证据自动溯源高亮，键盘快捷审阅
  4. 知识库：变异/基因检索，按 ACMG 证据维度分组的证据矩阵，支持 AI 自然语言查询，导出 CSV 或生成 ACMG 分类报告
  5. 反馈闭环：专家修正通过 Delta 审计静默记录，用于优化模型提取能力
- **输出**：ACMG 证据报告（JSON / PDF）、专家审查记录、Delta 审计日志

> **当前实现状态**：已实现 Pipeline 流水线提交与监控、Evidence Search 证据检索、Chat 对话功能。完整的 4-tab UI（AI 助手、任务看板、知识库查询、设置）尚在规划中。

## 端到端数据流

```
用户输入（关键词/DOI/PDF）
    │
    ▼
[Phase 1] 文献获取 → 结构化文档
    │
    ▼
[Phase 2] 跨语言翻译 + 双轨证据提取 → 双语证据 + 质量报告
    │
    ▼
[Phase 3] 实体标准化 + 数据库比对 → 标准化证据
    │
    ▼
[Phase 4] 可视化展示 + 专家审查 → 最终 ACMG 报告
```
