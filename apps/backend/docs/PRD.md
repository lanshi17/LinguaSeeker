# 多语种遗传证据平台 PRD

## 1. 文档信息
- 文档名称：Product Requirements Document (PRD)
- 项目代号：Multi-ACMG Evidence Platform
- 发布号：`v1.0`
- 当前状态：`v1.0` 规格冻结（多源获取 + 六节点工作流）

## 2. 产品目标与优先级
- 第一优先目标：可解释性（重点为“证据来源可解释性”）
- 目标用户：遗传咨询师、临床医生、研究员
- 使用场景：科研方法展示与验证

## 3. 用户与权限
- 业务用户权限：统一权限（不区分遗传咨询师/临床医生/研究员）
- 运维权限：独立体系，不在业务用户权限模型内
- 登录注册：
1. 邮箱注册
2. SMTP 邮箱验证码验证
3. 验证码有效期 5 分钟
4. 重发限制 1 分钟（按邮箱维度）
5. 每邮箱每天最多 20 次验证码请求
6. 密码策略：至少 8 位，且同时包含字母、数字、特殊字符

## 4. v1.0 范围
### 4.1 In Scope
1. 交互 Agent 将模糊意图转换为任务单
2. 主流程 6 节点：文献获取 -> 文档解析 -> 多语言处理 -> 证据提取 -> ACMG 分类 -> 专家裁决
3. 支持用户上传文献并跳过文献获取
4. 文献获取支持 API + 网页爬取的多源融合策略
5. 每篇文献独立 Celery 任务
6. 请求级聚合与进度追踪
7. 输出完整 JSON 溯源链（节点输入/输出/证据定位/来源）
8. 文档解析、翻译、证据提取作为独立微服务运行
9. KG 独立服务（先存库，后续服务从 PG 更新图谱）

### 4.2 Out of Scope（v1.0）
1. 非法或未授权数据源接入
2. 绕过版权/付费墙的抓取策略
3. pgvector 迁移（v1.0 保留 Qdrant）

## 5. 核心业务规则
### 5.1 交互任务单
- 输出形式：自然语言任务单
- 固定字段：`目标`、`疾病`、`国家`、`语种`
- 澄清轮次：最多 2 轮，之后按默认值自动执行
- 任务单落库：是（永久保存文本与结构化元数据）
- 默认值白名单（v1.0）：
1. `country=不限`
2. `language=auto`
3. `source=multi_source`
4. `candidate_limit=20`
5. `select_limit=5`
6. `fulltext_policy=fulltext_first_then_abstract`
7. `time_range=10y`

### 5.2 国家与数据源
- 国家判定方式：语种识别 + 数据库来源（非作者单位/研究对象地）
- 国家映射表使用 ISO 代码
- 未覆盖国家：返回 `FETCH_NO_RESULT`
- v1.0 数据源（可由调度智能体按任务动态组合）：
1. API：`biopython/pubmed`、`pmc`、`crossref`、`doaj`、`jstage`、`unpaywall`
2. 爬取：`hans_publishers`、`pubscholar`、`cyberleninka`
- 不允许降级为“语种近似国家过滤”

### 5.3 文献候选与选择
- 候选列表排序：`时间 > 相关性 > 证据强度`
- 候选总上限：20
- 分页：`default_page_size=5`，`max_page_size=5`
- 用户选择范围：最少 1 篇，最多 5 篇
- 用户未选择且未上传：返回 `failed + INPUT_INVALID`
- 用户只选 1 篇：立即执行，不再追问

### 5.4 上传与去重
- 上传格式：PDF、DOCX
- 上传限制：最多 10 个文件、单文件 <=10MB、总大小 <=50MB
- 去重策略：全库 `SHA-256`（按单个文件）
- 命中重复行为：
1. 新建 `paper_task_id`
2. `paper_task.status=success`
3. 标记 `FILE_DUPLICATE`
4. 跳过处理
5. 响应返回 `duplicate_of=<historical_paper_task_id>`
- `FILE_DUPLICATE` 计入成功率分子与分母
- 若一次请求全部为重复文件：请求级状态为 `success`

### 5.5 文档解析与多语言处理
- 文档格式支持：PDF 扫描版、PDF 文本版、DOCX
- 文档解析服务（独立微服务）：
1. 优先 MinerU API
2. 失败回退 PaddleOCR-VL-1.5
3. 保存结构化 `md` 与 `jpg` 到 MinIO
- DOCX 解析失败：直接失败
- 多语言处理服务（独立微服务）：
1. 原文英文跳过翻译
2. 非英文全文翻译为英文
3. 英文 `md` 写入 MinIO
4. 通过 `BGE-M3` 生成向量并写入 Qdrant
5. 对齐信息写入 PostgreSQL alignment 表

### 5.6 证据提取、ACMG 分类与专家裁决
- 证据提取服务（独立微服务）：
1. 采用 `scispaCy + LlamaIndex`
2. 实体识别：基因、变异、蛋白、疾病、实验术语
3. 关系抽取：基因-变异-疾病关系
4. 实验信息抽取：方法、结果、结论
5. RAG 混合检索：关键词检索 + 向量检索 + `juniper-bge-reranker-large_v2` 精排
- ACMG 分类智能体：基于 ACMG 指南知识库（RAG）输出分类结果与推理链
- 专家裁决智能体：基于 RAG 证据汇总确定证据强度
- v1.0 ACMG 范围：仅 PS3/BS3

### 5.7 输出与可解释性
- 输出 JSON 必须包含完整溯源链：
1. `request_id` / `paper_task_id`
2. 每节点输入摘要、输出摘要、耗时与状态
3. 证据片段坐标、来源链接、原文/英文对齐定位
4. ACMG 分类与专家裁决依据

## 6. 技术与流程约束
- 工作流编排：LangGraph（单篇文献粒度）
- 异步执行：Celery（每篇文献一个任务）
- 缓存：Redis
- 请求聚合：`request_id` 管理多个 `paper_task_id`
- ID 格式：`request_id`、`paper_task_id` 均为 UUIDv4
- 节点调度与重试：
1. 节点顺序固定为 6 节点
2. 数据源调用顺序与源级重试由 LLM 调度策略动态决定
3. 节点级默认重试模板与兜底上限见 `docs/CONSTANTS.md`
- 失败处理：默认终止；可由运维脚本手动重开（复用原 `paper_task_id`）
- 运维重开日志：记录 `reopened_by_ops_script`

## 7. 状态机定义
### 7.1 请求级状态
- `queued`
- `running`
- `partial_failed`（至少 1 成功且至少 1 失败）
- `failed`
- `success`（所有入选文献成功；或全部重复且跳过）

### 7.2 文献级状态
- `queued`
- `running`
- `success`
- `failed`

## 8. 错误码与告警
**单一来源**：见 [`docs/CONSTANTS.md`](CONSTANTS.md)。

## 9. 幂等与事件
**单一来源**：见 [`docs/CONSTANTS.md`](CONSTANTS.md)（幂等键格式 / KG 事件载荷最小字段）。

## 10. 数据保留策略
- 任务单文本与结构化元数据：永久
- 原始文件：不自动删除（允许运维手动清理）
- 解析中间文件：7 天
- 运行日志：7 天

## 11. 安全与访问
- `log_link`：签名临时 URL，有效期 24 小时
- 过期后允许重签发
- 重签发限流：每 `task_id` 每分钟 1 次
- 重签发访问者：任意已登录用户可调用

## 12. 合规边界
- 仅使用合法来源与授权访问
- 不设计、不接入绕过版权/付费墙方案

## 13. 验收标准（v1.0）
1. 支持 6 种语言（中英日法德俄）
2. 固定验收集 100 篇（同发布号内清单锁定不变）
3. 文献级成功率 >=95%（分母包含 `FILE_DUPLICATE`）
4. 单篇端到端时长 <=30 分钟（从 worker 开始计时）
5. 请求、文献、日志、报告、错误码链路完整可追踪
