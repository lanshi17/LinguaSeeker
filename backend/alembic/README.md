# Alembic

> Database migration environment for the LinguaSeeker backend. Manages PostgreSQL schema migrations for the `acmg_app` schema.

## Directory Map

```
alembic/
└── versions/          # Migration scripts (auto-generated by Alembic)
    └── .gitkeep
```

## Quick Start

```bash
cd backend

# Generate a new migration (auto-detect model changes)
uv run alembic revision --autogenerate -m "description of changes"

# Apply all pending migrations
uv run alembic upgrade head

# Rollback one migration
uv run alembic downgrade -1

# Check current migration head
uv run alembic heads

# Check current DB version
uv run alembic current
```

## Configuration

Alembic configuration is in `database/alembic.ini` (project root `database/` directory). The migration environment (`env.py`) is in `database/migrations/`.

The target metadata is `src.dao.postgresql.models.Base` — the SQLAlchemy declarative base containing all write-model tables.

## Architecture

```
database/
├── alembic.ini              # Alembic configuration
├── migrations/
│   ├── env.py               # Migration environment (imports Base.metadata)
│   └── script.py.mako       # Migration template
└── seeds/                   # Seed data (placeholder)

backend/alembic/
└── versions/                # Migration scripts location
```

## Key Design Decisions

- The write-model schema (`Base.metadata`) is the Alembic autogenerate target.
- The read-side projection (`frontend_search_index`) uses standalone `MetaData` so autogenerate does not treat it as write-model drift.
- pgvector extension and `TerminologyEmbedding` column are managed via dedicated migrations.
- Migrations are tested in `backend/tests/dao/postgresql/test_alembic_migration.py`.

## Testing
