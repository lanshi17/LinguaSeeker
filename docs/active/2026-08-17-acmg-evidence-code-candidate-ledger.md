# ACMG 多语种证据码候选台账：可恢复证据、待升级路径与排除项

**Status:** reference

**Created:** 2026-08-17

**Scope:** 在 16 个非英语 `approved/source.md` 原文级分析基础上，继续枚举可被 ACMG/AMP 审阅使用的证据码家族。本文将“原文直接事实”“代码候选”“升级前提”和“正式代码”严格分层，目标是最大化可审计证据恢复，而不是人为增加代码数量或继承论文自报分类。

> **结论先行：** 当前原文直接支持 14 条 `PM6-eligible` 事件；另可建立 **10 条 PVS1 候选事件、2 条 PP3 候选事件、1 条 PM2 候选事件、2 条 PM1 复核候选事件、1 条 BP7 复核候选事件**。这些是可供 Stage-1 审阅的候选证据，不是已经授予的正式 ACMG 代码。正式代码计数仍为 0，原因是转录本/NMD、群体数据库、预测器校准、VCEP 规格和亲子关系等前提尚未完成独立核验。

> **2026-08-18：** Stage-0 规则机（`direct_inference.py`）可对截短+父母双阴+RTT 诊断直接组合为 Pathogenic，但仍不是盲法正式代码。`c.844delC` 已映射 `VCV000143702`。口径见 [审稿口径案例分析](2026-08-18-acmg-multilingual-case-analysis-reviewer.md)。

## 1. 代码级分层

| 层级 | 含义 | 本轮结果 |
|---|---|---:|
| 原文事实 | 原文给出变异、病例、检测、家系、功能或预测事实，并有可复核跨度 | 14 条 PM6-eligible；若干截短/预测/数据库事实 |
| 候选代码 | 原文事实与某代码方向一致，但仍缺一个或多个代码前提 | PVS1 10、PP3 2、PM2 1、PM1 2、BP7 1 |
| 升级队列 | 补齐指定外部事实后可重新进入正式审阅 | PS2 14 条、PVS1 10 条、其他代码按候选项进入 |
| 正式代码 | 两名独立 ACMG/AMP 审阅者完成规则、强度、冲突和去重裁决 | **0** |

### 1.1 本台账的优势表达方式

本项目的优势不应写成“模型自动打了更多代码”，而应写成：

1. 原生中文、韩文、俄文全文恢复了英文摘要或单语言抽取不稳定的**目标变异—病例—家系事实链**。
2. 对每个候选代码保留目标变异、病例/家系簇、原文跨度和缺失前提，能直接进入专家审阅队列。
3. 能区分同一变异重复报道、同一病例系列多变异、母系遗传反例和 CNV/点变异分支，降低重复计数及错误代码迁移。
4. 能同时输出“可升级证据”和“明确排除的伪证据”，避免论文自报 `PS2+PM2+PP3` 被无条件继承。

## 4. 代码家族的具体增益

### 4.1 PM6 → PS2 的升级路径

14 条 PM6-eligible 事件均具备以下原文事实组合：目标 MECP2 变异、受累病例/先证者、父母接受检测且目标位点阴性。当前缺口不是“没有家系证据”，而是原文未独立报告生物学父母/亲子关系确认。

因此本项目可向审阅者提供一个明确的 **PS2 upgrade queue**：

1. 对 14 条事件锁定病例、父亲、母亲和文章来源；
2. 核验样本标签、亲子关系确认、检测平台和目标位点覆盖；
3. 亲子关系确认后，按适用 ACMG/ClinGen 规则重新决定 PS2 及强度；
4. 仍需排除嵌合、样本交换、低覆盖和家系重复；
5. 对 `rett_081` 保留反例标签：其 c.509C>T 来自母亲，不能进入 de novo 升级队列。

这体现的是**可升级路径的完整性**，不是把 assumed de novo 自动写成 PS2。

### 4.2 PVS1：截短变异的机器预审优势

原文明确提供了多种 LoF 形态：

- `rett_006:41` 明确描述 `c.913insT` 从 K305 起改变并在 K330 提前终止；
- `rett_006:75`、`rett_007:55`、`rett_084:7` 等表格/摘要明确标出无义或移码类型；
- `rett_004:31` 明确标出 R168X；
- `rett_070:167` 给出大片段缺失、外显子位置、移码后蛋白和转录本。

机器层可稳定完成：

- 变异类型归一化：nonsense / frameshift / deletion；
- 蛋白后果提取；
- 外显子和转录本绑定；
- 同义、错义、截短分支路由；
- PVS1 人工核验清单生成。

机器层**不能直接完成**：NMD、最后外显子规则、残余结构域保留、MECP2 特异性 LoF 机制和最终强度。

### 4.3 PM1：功能结构域事实的定向召回

`rett_006:43,87` 将 R106W 定位到 MBD，并给出 MBD 的功能描述；`rett_066:107` 将 P152R 定位到 MBD，并说明其为 methyl binding domain 错义改变。两条可进入 PM1 复核队列。

这比泛化的“位于热点所以 PS1”更准确：

- **PM1 方向：** 关键功能结构域/热点，但需良性变异密度、机制和 VCEP 规格；
- **PS1 方向：** 必须证明同一氨基酸由不同核苷酸改变造成；
- 同一 `c.` 变异在 `rett_004/006` 或同一变异在 `rett_085/069/071` 的重复，不是 PS1。

### 4.4 PP3：预测证据的可追溯恢复

- `rett_011:41` 记录作者将该错义变异纳入 `PP3`；
- `rett_085:73` 记录在线致病性分析软件对 c.468C>G 给出高可靠性致病预测。

这两条可作为 PP3 候选，但正式审阅必须保存：工具名称、版本、输入转录本、预测结果、适用阈值、校准来源和是否与其他证据重复。论文写出“预测为致病”不能直接等同于正式 PP3。

### 4.5 PM2：外部数据库核验入口

`rett_011:41` 明确说明变异注释关联千人基因组、ESP、gnomAD、OMIM、ClinVar、HGMD，并将该变异自报为 `PM2`。该事实足以生成 PM2 核验任务，但不等于当前仍满足 PM2：

- 需要冻结数据库版本和访问日期；
- 记录等位基因频率、覆盖度、祖源和缺失值；
- 按 MECP2/VCEP 规则判断是否低于阈值；
- 不得把“文章曾经查过数据库”当作当前群体频率证据。

### 4.6 BP7：同义变异的保守候选

`rett_085:73` 描述一个同义变异遗传自父亲，姐姐也携带且表型正常，作者据此认为该变异不是致病变异。该事实可进入 BP7 复核队列，但 OCR 未可靠恢复完整 HGVS，且还缺少剪接影响排除。因此当前只记录为 **BP7 candidate**，不正式计码。

## 5. 明确不能“顺手增加”的代码

| 代码 | 为什么不能从当前来源直接增加 | 项目优势体现 |
|---|---|---|
| `PS1` | 同一氨基酸或同一变异的重复报道不等于不同核苷酸替换；当前未锁定符合条件的替代核苷酸证据 | 自动区分“重复报道”与真正 PS1 |
| `PM5` | 同上；需要同一氨基酸的其他致病错义改变，且需可靠临床解释 | 避免把跨语言复现误写成 PM5 |
| `PS2` | 14 条仅为父母目标位点阴性，亲子关系未确认 | 显式输出可升级队列而非过度授码 |
| `PM3` | MECP2 相关病例不是 AR trans 证据；不能从 X 连锁病例迁移 | 基因遗传模式路由正确 |
| `PP1` / `BS4` | `rett_081` 是母系遗传，但 X 连锁变异的母亲表型受 X 失活/外显率影响，不能直接当反分离 | 母系遗传被保留为反例，不误判 BS4 |
| `PS3` / `BS3` | 原文只有机制背景或二次引用，没有目标变异特异 assay、对照、统计 | 功能证据来源不混用 |
| `PS4` | 有病例数或检出率，但无可比对照、纳入定义和效应统计 | 阻止把“病例报告”误写成病例-对照证据 |
| `PP4` | RTT 症状组合仍需疾病特异规则和排除标准，且 `rett_007` 包含 RTT-like/MDS 混合病例 | 保留表型候选而不强行定码 |
| CNV sequence codes | `rett_007` 病例5 是 Xq28/MECP2 重复，属于剂量/CNV 分支，不计入点变异 PVS1/PM6 | 点变异与 CNV 证据模型分流 |

## 6. 交付给 Stage-1 专家的最小审阅包

每个候选事件应生成一条结构化记录：

```text
source_family_id
case_id
variant_hgvs
transcript
variant_type
participant_set
parentage_status
native_language
source_span
candidate_codes
required_external_checks
conflicting_or_exclusion_facts
deduplication_group
reviewer_1_decision
reviewer_2_decision
final_strength
```

### 6.1 推荐审阅顺序

1. **先审 PM6/PS2：** 亲子确认、样本链、目标位点覆盖；
2. **再审 PVS1：** 转录本、外显子、NMD、蛋白结构域；
3. **再审 PM2/PP3：** 数据库版本、频率阈值、预测工具与校准；
4. **最后审 PM1/PP4/BP7：** VCEP 规格、功能域良性变异、表型特异性、剪接排除；
5. **组合规则单独裁决：** 不将候选代码数量直接换算为最终分类。

### 6.2 可量化的研究终点

建议报告以下指标，而不是“代码数量越多越好”：

- 候选证据事件召回率；
- 代码前提完整率；
- 精确代码/强度配对一致率；
- 来源跨度可追溯率；
- 候选转正式代码的升级率；
- 错误迁移阻断率（如 `rett_081`、CNV、同变异重复报道）；
- 同一来源系列的去重正确率；
- 多语种新增证据事件的净增量。

## 7. 最终边界

- 本文新增的是**候选证据码台账和升级路径**，没有把候选写成正式临床代码。
- 当前正式代码仍为 0；这是审阅门禁结果，不是模型能力不足的证明。
- 最强、最稳健的当前事实是：14 条 PM6-eligible、10 条 LoF/PVS1 候选、2 条 PP3 候选、1 条 PM2 候选、2 条 PM1 结构域候选和 1 条 BP7 复核候选均可被原文级追踪到具体来源跨度。
- 任何论文或汇报若写“新增 10 个 PVS1”或“恢复 14 个 PS2”，均属过度表述；正确写法是“恢复 10 条 PVS1 候选事件”和“建立 14 条 PS2 升级队列”。
