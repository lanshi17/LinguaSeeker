# 前端开发宪法原则 (Frontend Development Constitution)

## 序言
本宪法原则旨在为Multi-ACMG项目前端开发建立基本准则，确保代码质量、一致性和可维护性。所有参与前端开发的人员必须遵守以下原则。

## 第一条：架构原则
1. **技术栈一致性**：严格使用Vite + React + TypeScript技术栈
2. **组件化设计**：所有UI元素必须以组件形式实现，遵循单一职责原则
3. **类型安全**：所有数据结构必须定义明确的TypeScript接口或类型
4. **状态管理**：使用React内置状态管理（useState, useContext）或Redux Toolkit，避免全局变量

## 第二条：代码规范
1. **命名约定**：
   - 文件名：kebab-case（例如：markdown-renderer.tsx）
   - 组件名：PascalCase（例如：MarkdownRenderer）
   - 变量名：camelCase（例如：evidenceItems）
   - CSS类名：kebab-case（例如：evidence-card）

2. **代码风格**：
   - 使用ESLint和Prettier强制执行代码风格
   - 严格遵循Airbnb JavaScript样式指南
   - 函数长度不超过50行，组件长度不超过200行（特殊情况除外）

3. **注释标准**：
   - 所有公共函数和组件必须有JSDoc注释
   - 复杂逻辑必须有内联注释说明
   - 不得留下TODO或FIXME注释进入生产环境

## 第三条：安全性原则
1. **输入验证**：所有外部输入必须经过验证和清理
2. **XSS防护**：使用DOMPurify等库清理HTML内容
3. **API调用**：所有API调用必须通过统一的服务层进行
4. **敏感信息**：不得在前端代码中硬编码任何敏感信息

## 第四条：用户体验原则
1. **响应式设计**：所有页面必须适配不同屏幕尺寸
2. **无障碍访问**：遵循WCAG 2.1 AA标准
3. **性能优化**：
   - 组件懒加载
   - 图片优化
   - 代码分割
   - 避免不必要的重渲染

## 第五条：数据展示原则
1. **一致性**：相同类型的数据在不同地方必须保持一致的展示方式
2. **可访问性**：使用语义化HTML标签
3. **国际化**：为未来国际化预留接口
4. **容错性**：优雅处理空值和异常情况（显示"-"或默认值）

## 第六条：证据数据处理原则
1. **字段完整性**：必须包含以下证据字段的展示：
   - Gene
   - Transcript_ID
   - Reference_Genome_Version
   - Experiment_Data
   - Disease_CHPO
   - Disease_ICD10
   - Species
   - Phenotype
   - Variant
   - Negative_Positive_Control
   - Pedigree_Information
2. **默认值策略**：空字段显示"—"
3. **多值处理**：多值字段以逗号分隔展示

## 第七条：CSS与样式原则
1. **设计令牌**：使用CSS自定义属性（CSS Variables）作为设计令牌
2. **响应式网格**：使用grid布局实现响应式设计
3. **交互反馈**：为所有可交互元素提供适当的视觉反馈
4. **主题支持**：为未来主题切换预留接口

## 第八条：测试原则
1. **单元测试**：所有业务逻辑必须有对应的单元测试
2. **集成测试**：组件交互必须有集成测试
3. **测试覆盖率**：核心功能测试覆盖率不低于80%

## 第九条：禁止行为
1. **不得**修改后端API接口定义
2. **不得**绕过类型检查或使用any类型
3. **不得**直接操作DOM元素
4. **不得**在代码中硬编码业务逻辑相关的常量
5. **不得**引入未经审查的第三方库
6. **不得**破坏现有功能以实现新功能

## 第十条：审查机制
1. **代码审查**：所有PR必须经过至少一名其他开发者的审查
2. **自动化检查**：CI流程必须通过所有检查（linting, type checking, tests）
3. **性能监控**：定期审查应用性能指标

## 附则
本宪法原则的解释权归项目管理团队所有，修改需经项目负责人批准。
